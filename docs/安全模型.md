# BlackLang 安全模型（三层纵深）

BlackLang 面向 AI/代理：**AI 生成代码的安全是「默认值」，不是「可选项」**。
不能信任 AI 写的每一行代码，所以 BlackLang 在**运行前、运行中、边界上**都设了墙。

## 三层防御

### 第 1 层 · 编译期拦截（`--check` / `api.run` 前置）
运行之前先做两类静态分析，**任何不过都不执行**：

- **能力分析（`static_check`）**：扫描所有需要权限的操作（`read`=readonly-fs、
  `http_get/post`=net、`write`=write-fs）。凡出现在未授权 `sandbox caps: {}`
  作用域内外无授权的能力调用，编译期直接拒绝并给出行号——AI 改完即可自检重试。
- **类型检查（`type_check`）**：类型推断与一致性，AI 的类型错误当场可见而非运行期炸。

顶层 `run main` 依赖 `api.run`/`blacklang <f>`：**静态检查失败 → 拒绝执行**（安全默认）。
报错形如：
```
[BlackLang 编译期拦截，未执行]
  ✗ 编译期越权拒绝: http_get 需要权限 'net'，但当前作用域未授予（请置于 sandbox net: { ... } 内）
```

### 第 2 层 · 运行期强制（树遍历求值器 / 宿主编排）
即便静态分析无法 100% 证伪（例如 interop 的不可静态证明路径），运行期仍按
当前 `sandbox` 累积的权限 `caps` 强制：未授权的能力调用运行期抛错。`use python`
的导入也受当前 sandbox 能力约束。

### 第 3 层 · 跨进程墙（`--sandbox` / `api(sandbox)`）
`blacklang --sandbox f.bl [--timeout N]` 把程序放进独立子进程：
- 程序崩溃 / 抛异常 → 只影响子进程，宿主进程零影响；
- 死循环 / 超长任务 → 父进程到点 `terminate()`，已实测 ~1s 强制终止；
- 子进程内**依然**先做编译期拦截 + 运行期强制（三层同时在场）。

```
编译期拦截(静态, 不漏)  →  运行期强制(逐调用)  →  跨进程墙(隔离/限时)
     同一份代码三层全部生效，任何一层都不信任下一层的完备性。
```

## 与「能力清单」配合（给 AI/工具链的自证）

`blacklang --manifest f.bl` 输出程序的**能力占用 JSON**（program_caps / per_function /
unauthorized_calls / 编译结果）。AI/Agent 可在运行前做**运行前自证 + 审计**：
`manifest` 帮你判断"这段代码要不要、要哪些权限"，再决定是否放行。

## 与「结构化诊断」配合（给 AI 自纠）

拦截信息不是一坨文字，而是稳定的机器可读结构：

```bash
blacklang --check f.bl --json       # 或 Python: bl.diagnose(source)
```

```json
{"ok": false, "diagnostics": [{"severity": "error", "code": "BL1001",
  "stage": "capability", "message": "编译期越权拒绝: http_get 需要权限 'net' …",
  "hint": "把该调用放进授予对应权限的 `sandbox <权限>: { … }` 内；或去掉该调用"}]}
```

安全相关错误码：`BL1001` 能力越权（编译期拒绝）、`BL2001` C 后端不支持的构造
（会回退而非带病执行）、`BL9002` 沙箱超时。AI 按 `code` 决策、按 `hint` 修复即可闭环。

## 常见问题

- **"我明明给了 `sandbox net: {}` 为什么还拦截"** → 该能力调用需出现在授予它的
  `sandbox` 作用域**之内**；在作用域之外的同类调用仍属越权。
- **"`read` 读不了文件"** → `read` 只在 `sandbox readonly-fs: {}` 内被授权；默认拒绝。
- **"子进程超时了"** → 说明程序确实跑得久或死循环；用 `--timeout` 调墙，同时排查是否真的
  需要那么长。超时不会外溢到宿主（已实测）。

## 验证

- 单元/集成测试覆盖：`TestSandbox`（正常/越权/超时/运行期）、`TestAiTool`（工具层拦截）、
  `TestBusinessDemo`（business demo 安全落点）。
- 实测记录：
  - 死循环交互 `while 1>0: print` → 运行期循环上限拦截（<150ms）；
  - 重计算超时 → 跨进程墙 ~1s 强制终止（`timed_out=True`）。
